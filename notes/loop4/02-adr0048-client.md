# Item 2 — `movie.noyear` / ADR-0048: **it is a UI slice, and it belongs elsewhere**

The board asked for a decision rather than an implementation. This is it.

## The server half is complete

`fix::search_candidates` marks at most one candidate `suggested` — the id the
shipped `score_search` chose and the floor then declined. Movies only;
`SearchKind::Tv` returns `None`, with the reason written down (a show scored on
this route would be scored without the season shape the drain has, and would be
a different signal wearing the same badge). Nothing assigns on the flag.
`assign` still takes the id the user sent.

That is ADR-0048 option B exactly as the record specifies it. Nothing is missing
on the server.

## Nothing reads it — and it is worse than the board says

Verified across every non-server file in the tree, all extensions, excluding
`node_modules`, `build`, `dist`, `target`:

  * `web/src/lib/api/schema.d.ts` names the route and the field, and is
    **auto-generated** — "This file was auto-generated by openapi-typescript.
    Do not make direct changes." A type, not a caller.
  * `api/openapi.yaml` documents it.
  * **No `.ts`, `.tsx`, `.js`, `.svelte`, `.vue`, `.kt`, `.swift` or `.dart`
    file anywhere references `candidates`.**

And the gap is not one field. **The whole metadata fix flow has no client:**

| route | callers |
|---|---|
| `GET  /items/{id}/metadata/candidates` | 0 |
| `POST /items/{id}/metadata/assign` | 0 |
| `POST /items/{id}/metadata/clear` | 0 |
| `POST /items/{id}/metadata/retry` | 0 |

`web/src` calls 22 endpoint families — accounts, artwork, auth, items,
libraries, profiles, scan-jobs, series, sessions, system. **None under
`/metadata/`.**

## The decision

**This is not matcher work and it is not one badge.** Wiring `suggested` into a
fix flow requires a fix flow, and there is no fix flow. That is a client slice
of at least four routes — search, assign, clear, retry — with its own design
questions about how a below-floor suggestion is presented so a user does not
read a rank as an answer.

**The item closes here.** The server half is complete; the client is recorded as
outstanding and belongs to whoever takes the fix-flow UI.

## What no instrument can say about it

ADR-0048 says so itself, and it is right:

> B moves no oracle row — a below-floor suggestion still scores `absent` — so
> this record cannot be validated by `correct%` and should not be.

`movie.noyear` reads **705 absent** on this loop's corrected baseline, the same
705 as before the instrument was fixed. A suggestion the user has not yet
accepted is still an unmatched file, and it should be. **The oracle is
insensitive to this item by construction**, and deliberately so — what B changes
is the cost of the fix flow, which the oracle does not model at all: no manual
match, no rescan, no second pass.

So there is nothing here to measure, and no measurement should be reported as if
there were.

**Runtime stays excluded**, and the reason is unchanged: the harness generates
`duration_ms` from the correct entity's own runtime, so anything reading a
duration marks its own homework.
